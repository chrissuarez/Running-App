A, when the plan is missing and when the kit is broken

You picked A, and asked what it looks like when things are missing or broken. Those turned out to be two different questions, and the second one uncovered something in the code that changes the ticket.

Found while mocking this

The app has no Start button today, and my earlier mock quietly invented one. Right now the run begins the moment the chest strap connects — onConnected sets the session to RUNNING and opens the database record (HrForegroundService.kt:1793). The buttons on the screen say “Start Service” and “Scan Devices”; neither is “start my run”. Connecting is starting.

So “no strap” isn’t a cosmetic broken state — today it means no run at all, and you have no way to record one without the strap. A big blue START changes that rule. That’s a decision for you, not a detail, and it’s what the last two phones below are asking.

Missing: nothing is wrong, there’s just no plan

Your open-ended run — the case that replaces Free Track. The first phone is the everyday one for reference. The question is whether the other two feel deliberate or feel like a hole.

Broken: the strap or the GPS isn’t there

Here the screen has to say something is wrong without becoming a wall of diagnostics — today’s “Run Setup” card reports sensor readiness, raw connection status and testing mode in three separate lines, which is four more facts than 6am can use.

What I’d land on

One card slot, one sensor line, one START, in the same three places every single morning — the card says what you’re about to do, the line says what’s wrong if anything is, and START is always alive. Nothing on this screen is ever an empty box, and nothing on it is ever a dead end.
