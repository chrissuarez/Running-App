# The Plan is a menu, not a cursor

A Stage offers one Workout of each Run Type, and the runner picks which of them
today's Run is (#174). The app keeps no position in the Plan: nothing records
which Workout was due, which week it is, or which of the three was run last.

That is the whole point. A stored position has to answer questions the app
cannot honestly answer — what happens to a Workout that was due on Tuesday and
not run, what a second Run in one day means, which day a Run started at two
minutes to midnight belongs to. Every one of those is a rule someone has to
invent, and every invented rule is a place the app can tell the runner they are
behind on a schedule the app made up. With no position, the questions never come
up: the Stage's three Workouts are all always on offer, and picking one is the
whole of choosing today's Run.

## Consequences

- **Nothing stops Quality three times a week.** The runner holds the training
  structure, not the app. This is accepted, not overlooked — a suggestion of
  which to run can be added later without changing anything here, because a
  suggestion is not a position.
- **A Pick is worth as long as the screen that made it.** It travels with START
  so the Run is the one the card was showing, and it is never written down. A
  Pick that outlives the Stage it was made in falls back to that Stage's first
  Workout rather than detaching the Plan.
- **The AI coach has no queue to write into.** It prescribes work for a Run Type
  (see *Prescription* in `CONTEXT.md`), and which Run Type comes next is not a
  thing the app knows.
